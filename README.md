# SocialSync media Worker · 1.0.0

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/shahibul003-star/socialsync-media-worker)

This standalone connector stores your workspace's originals in your private Cloudflare R2 bucket. The SocialSync application repository is separate. No SocialSync server key, provider credential, account ID or customer secret belongs in this repository.

## Connect without a terminal

1. Open SocialSync → Workspace settings → Media storage. Generate and copy a connection secret. Keep this page open.
2. Click **Deploy to Cloudflare**. Sign in to Cloudflare and authorize GitHub or GitLab. Cloudflare copies this template into your own Git account. Enable R2 in Cloudflare if prompted; its billing setup is controlled by Cloudflare.
3. Choose the Worker and bucket names. Cloudflare provisions the `MEDIA` R2 binding automatically. Leave the bucket private and disable public development URLs.
4. Paste your SocialSync secret into `MEDIA_SIGNING_SECRET`. Check that `APP_ORIGINS` matches the exact origin shown in SocialSync. Click Deploy and wait for a successful build.
5. Copy the deployed HTTPS `workers.dev` URL. Return to SocialSync and paste it beside your secret. Click **Verify and connect**. SocialSync tests upload, read, range read, unauthorized access and deletion of a temporary object.

You own the Worker, bucket, Cloudflare bill and copied repository. There is no SocialSync total-storage quota on customer-owned R2. File-size safeguards still apply; the workspace owner can set an optional application budget. Cloudflare free allowances apply across your Cloudflare account, not separately to every bucket.

## Dashboard fallback

Download the versioned connector package from SocialSync. Extract it and upload its files to a new GitHub/GitLab repository using the website. In Cloudflare → Workers & Pages → Create → Import a repository, select that repository. Use `npm run deploy` as the deploy command. Add the `MEDIA_SIGNING_SECRET` secret and confirm the `MEDIA` binding. After deployment, perform step 5 above. Keep `.env` and `.dev.vars` out of Git.

For a dashboard-only Worker, Cloudflare's editor can use a bundled ES module generated by Wrangler; the source package is designed for the native repository deployment flow. Do not paste TypeScript into a JavaScript editor without building it.

## Upgrade and rollback

Record your installed version in SocialSync's connection status. Review a tagged connector release and its changelog. In your copied repository, replace only `src/` and update `package.json`/lockfile from that release. Preserve your provisioned R2 bucket binding, Worker name, variables and secret. Deploy, then run SocialSync's connection verification. Roll back using Cloudflare → Worker → Deployments → a previously verified version. Never delete or recreate a populated bucket during an upgrade.

To rotate the secret, deploy a **new Worker URL** and connect it in SocialSync. Keep the previous Worker and bucket running while any asset still references them. Existing assets and schedules remain pinned to their original connection; changing the current connection does not copy their objects.

## Protocol and limits

- Protocol 1; authenticated health returns version `1.0.0`.
- HMAC signed, expiring upload/read URLs; internal commands require a timestamped HMAC.
- Originals remain private. Unauthorized reads return 403; uploads cannot overwrite an existing object.
- General publishing uploads: 100 MB maximum. Automation images: PNG/JPEG up to 8 MB, additionally enforced by SocialSync.
- Range reads and HEAD are supported. Imported downloads follow an explicit HTTPS host allowlist.

See [Cloudflare's deployment flow](https://developers.cloudflare.com/workers/platform/deploy-buttons/) and [R2 pricing](https://developers.cloudflare.com/r2/pricing/).
